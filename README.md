# cs465-fullstack

CS-465 Full Stack Development with MEAN.

## Reflection on process:

The two types of development we did included Express Html, some JavaScript, vs the single-page application made with Angular. Both had different file types and file structures. Express HTML, while it did use hbs files to allow for easier chunking of files into separate parts for the most part rather then HTML, was fairly static and did was combines with JavaScript mostly to handle transferring between different pages and that alone. Compare to angular, which while it also had routers to send between pages, was used much more for getting information from API endpoints. Both broke up views into separate components that could be combined to make a page.

The backend used a NoSQL MongoDB database because it is a decently reliable and has reliable tools including an officially supported viewer as well as an official library to interact with it using code. It stores data, and is designed to allow for methods to speed up the search in specific instances, such as with indices. It can also save new added pieces of data. It stores with a variant of JSON. JSON is different from JavaScript in quite a few respects, despite coming from JavaScript. JSON is an incredibly restricted version of JavaScript consisting only of objects, arrays, strings, numbers, and Booleans, along with named pairs of a string to one of these other preexisting objects. It helps tie the frontend and backend together by giving a data format that can be easily communicated with using the power of text, despite the sometimes insanely different ways that programs handle data formatting. The database and website and code can all equally use the data gotten, and multiply libraries exist for automatically turning it into data types that are similar to the chosen JSON, allowing for easy transfer. In addition, it's still fairly human readable, so it can easily be understood as well.

In the full stack process, refactoring code included a lot of file decomposition, for example in the static site having header and footer files be separate files. Similarly, the trip list and the trip cards that are a part of the single application page are within their own pages, as well as a header. Other forms of refactoring including adding several routers later being added and included in app.js, and security's later addition was made with refactoring. The benefits of reusable user interface (UI) components include being able to use them on several different pages, if generic enough maybe even being able to use it to house multiple different types of content without much struggle. This also allows for more through branding if elements of a page always have the same style. Finally, if the element was well designed, such as not relying on color or being perfectly usable by someone with a screen reader, the company benefits from that as well.

Included methods for request and retrieval include GET, POST, and PUT; api endpoints used were api/register (with post), api/login (with post), api/trips (with get and post), api/trips/:tripCode (with get and put); Security in a full stack application needs these endpoints and methods to also support verification being necessary to use them. This course has helped me in reaching professional goals by encouraging me to be more willing to work with libraries and external code, as well as reaching how they may work in order to improve them. It also showed me how to design a website with a given set of tools. The skills I have learned also include git interaction, and how to automate uploading to it.
